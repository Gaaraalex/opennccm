1. Qué se instala y cómo funciona

OpenNCCM es una aplicación web que se instala en un único servidor Ubuntu. Se conecta a sus switches, routers y firewalls por SSH (o Telnet) para respaldar su configuración, compararla, auditarla y aplicar cambios. Los equipos le avisan de los cambios en tiempo real enviando mensajes syslog.

ComponenteFunción
nginxRecibe las conexiones HTTPS (puerto 443) y las pasa a la aplicación. Redirige HTTP (80) a HTTPS.
Servicio opennccmAplicación web (FastAPI + Uvicorn) escuchando solo en el propio servidor (127.0.0.1:8000). Incluye el planificador de tareas y el receptor syslog.
NetmikoBiblioteca que habla con cada fabricante por SSH/Telnet y SCP.
Base de datosSQLite en /var/lib/opennccm por defecto. Configuraciones y contraseñas cifradas.
Clave de cifrado/etc/opennccm/secret.key. Sin ella los datos no se pueden leer.

3. Preparar el servidor Ubuntu

Conéctese al servidor por SSH (desde Windows puede usar PowerShell, PuTTY o Windows Terminal):

PS> ssh USUARIO@IP_DEL_SERVIDOR

Actualice el sistema y configure la zona horaria (importante: las fechas de cambios y tareas usan la hora del servidor):

$ sudo apt update && sudo apt -y full-upgrade $ timedatectl list-timezones | grep America # buscar su zona $ sudo timedatectl set-timezone America/Mexico_City # ejemplo: use la suya $ timedatectl # verificar hora y "NTP service: active" $ sudo hostnamectl set-hostname opennccm # opcional $ sudo reboot # si se actualizó el kernel
RecomendaciónSi el servidor es una máquina virtual, tome una instantánea (snapshot) ahora. Permite volver a este punto si algo sale mal durante la instalación.

4. Copiar el paquete al servidor

El software se entrega en el archivo opennccm.tar.gz. Cópielo a la carpeta personal del usuario en el servidor.

Opción A — Desde Windows con PowerShell (scp viene incluido en Windows 10/11)

PS> cd C:\ruta\donde\esta\el\archivo PS> scp .\opennccm.tar.gz USUARIO@IP_DEL_SERVIDOR:~/

Opción B — Con WinSCP

  1. Abra WinSCP, protocolo SFTP, servidor IP_DEL_SERVIDOR, su usuario y contraseña.
  2. Arrastre opennccm.tar.gz a la carpeta personal (/home/USUARIO).

Descomprimir

$ cd ~ $ tar xzf opennccm.tar.gz $ cd opennccm $ ls app CHANGELOG.md install.sh README.md requirements.txt rollback-update.sh

5. Ejecutar el instalador

$ sudo bash install.sh

El instalador tarda entre 2 y 5 minutos según la conexión. Hace lo siguiente, en orden:

Al terminar, el instalador muestra un resumen como este (los valores de IP y contraseña serán los suyos):

==> Instalando OpenNCCM 1.1.0 en Ubuntu 24.04 LTS ==> Creando entorno Python ==> Generando clave AES-256 en /etc/opennccm/secret.key (¡respáldela! sin ella no se pueden leer los datos) ==> Configurando nginx con HTTPS (certificado autofirmado) Usuario inicial: admin Contraseña: (contraseña aleatoria) (cámbiela en 'Mi cuenta') OpenNCCM listo en https://IP_DEL_SERVIDOR/ Logs: journalctl -u opennccm -f Respalde SIEMPRE /etc/opennccm/secret.key junto con /var/lib/opennccm
Anote la contraseña inicialSe muestra una sola vez. Si la pierde, puede crear una nueva con sudo opennccm-cli reset-password admin 'NuevaClave123'.

Comprobar que el servicio está activo

$ systemctl status opennccm --no-pager ● opennccm.service - OpenNCCM - Network Configuration & Change Management Active: active (running) $ curl -k https://localhost/healthz {"status":"ok"}

6. Primer acceso

  1. En su PC abra el navegador y vaya a https://IP_DEL_SERVIDOR/.
  2. El navegador avisará que la conexión «no es privada»: es normal con el certificado autofirmado. Pulse Configuración avanzada → Continuar. Para quitar el aviso instale un certificado propio (sección 11).
  3. Ingrese con el usuario admin y la contraseña que mostró el instalador.
  1. Cambie la contraseña de inmediato: clic en su nombre de usuario (arriba a la derecha) → Mi cuenta.
Protección contra fuerza brutaTras 10 intentos fallidos desde la misma IP, el ingreso se bloquea 15 minutos. Cada intento queda en Auditoría.

7. Configuración inicial

7.1 Credenciales de los equipos

Menú Credenciales. Cree un perfil por cada combinación de usuario/contraseña que usen sus equipos (por ejemplo «red-admin» y «firewalls»). Si sus equipos Cisco requieren enable, complete también «Enable / secret». Las contraseñas se guardan cifradas y nunca se vuelven a mostrar.

En la misma página cree los grupos de dispositivos (sede, función o cliente). Los grupos sirven para tareas, políticas, filtros y para limitar qué equipos ve cada usuario.

7.2 Agregar dispositivos

Menú Dispositivos → + Agregar. Complete nombre, IP, fabricante/sistema operativo, protocolo, credencial y grupo. Al guardar, OpenNCCM hace el primer respaldo automáticamente.

7.3 Importación masiva por CSV

Para muchos equipos, prepare un CSV en Excel (guardar como «CSV UTF-8») con estas columnas y cárguelo al pie de la página Dispositivos:

name,host,device_type,credential,group,port,protocol,location
core-sw1,10.0.0.1,cisco_ios,red-admin,Core,22,ssh,Datacenter
fw-01,10.0.0.254,fortinet,firewalls,Seguridad,22,ssh,Datacenter
edge-r1,10.0.1.1,juniper_junos,red-admin,WAN,22,ssh,Sucursal Norte

El valor de device_type de cada plataforma está en Sistema → plataformas soportadas (página /vendors). Los grupos que no existan se crean solos.

7.4 Verificar el primer respaldo

Abra el dispositivo. Si el estado es ok verá su modelo, número de serie, versión de firmware y la primera versión de configuración. Si es error, el recuadro rojo indica la causa (ver sección 16).

8. Enviar syslog desde los equipos

Para que OpenNCCM detecte los cambios en el momento en que alguien los hace, cada equipo debe enviar sus mensajes syslog al servidor (UDP 514). Al recibir un aviso de cambio, OpenNCCM espera 20 segundos, respalda el equipo, compara, alerta y, si está activada, revierte el cambio no autorizado.

AtajoHay configlets listos para Cisco IOS, Junos y Huawei en Configlets → «Configurar syslog hacia OpenNCCM»: elija los equipos, escriba la IP del servidor en la variable servidor_ncm y apruebe.

Cisco IOS / IOS-XE

logging host IP_DEL_SERVIDOR
logging trap notifications
archive
 log config
  logging enable
  notify syslog contenttype plaintext

Juniper Junos

set system syslog host IP_DEL_SERVIDOR interactive-commands notice
set system syslog host IP_DEL_SERVIDOR change-log info
commit

Huawei VRP / H3C

info-center loghost IP_DEL_SERVIDOR

Fortinet FortiGate

config log syslogd setting
    set status enable
    set server "IP_DEL_SERVIDOR"
end

MikroTik RouterOS

/system logging action add name=ncm target=remote remote=IP_DEL_SERVIDOR
/system logging add topics=system,info action=ncm

Aruba / HPE / Arista

logging IP_DEL_SERVIDOR

El equipo debe estar dado de alta en OpenNCCM con la misma IP desde la que envía el syslog (o con un nombre DNS que resuelva a ella). Puede comprobar la recepción en Alarmas: aparece un evento «Syslog de cambio».

Menú Ajustes → Notificaciones. Configure uno o varios canales y pulse Enviar notificación de prueba.

CanalQué completar

La «severidad mínima» define qué se notifica: warning envía cambios de configuración, infracciones y fallos; critical solo reversiones automáticas y vulnerabilidades críticas.

11. Certificado HTTPS propio

El instalador crea un certificado autofirmado válido por 10 años. Para evitar el aviso del navegador, reemplácelo por uno de la CA de su empresa o de Let's Encrypt.

Certificado de su CA interna

$ sudo cp servidor.crt /etc/ssl/certs/opennccm.crt # incluya la cadena intermedia $ sudo cp servidor.key /etc/ssl/private/opennccm.key $ sudo chmod 600 /etc/ssl/private/opennccm.key $ sudo nginx -t && sudo systemctl reload nginx

Let's Encrypt (solo si el servidor tiene un nombre DNS público accesible por el puerto 80)

$ sudo apt install -y certbot python3-certbot-nginx $ sudo certbot --nginx -d opennccm.SU-DOMINIO.com

12. Cortafuegos

Si usa ufw, el instalador abre los puertos necesarios cuando ya está activo. Para activarlo desde cero sin perder su sesión SSH:

$ sudo ufw allow OpenSSH $ sudo ufw allow 'Nginx Full' $ sudo ufw allow 514/udp comment 'OpenNCCM syslog' $ sudo ufw enable $ sudo ufw status
Más seguroLimite el syslog y la web a sus redes de gestión, por ejemplo: sudo ufw allow from 10.0.0.0/8 to any port 514 proto udp.

13. Copias de seguridad y recuperación

OpenNCCM guarda todo lo importante en dos lugares:

RutaContenido
/var/lib/opennccmBase de datos (configuraciones, historial, usuarios, políticas), imágenes de firmware y copias.
/etc/opennccmsecret.key (clave de cifrado) y opennccm.env (configuración del servicio).

Desde la interfaz

Menú Sistema → Crear copia ahora. Programe la copia diaria en Tareas y, en Ajustes → Recuperación ante desastres, defina cuántas copias conservar y un servidor SFTP remoto donde enviar cada copia.

Desde la consola

$ sudo opennccm-cli system-backup # sin la clave $ sudo opennccm-cli system-backup --with-key # incluye secret.key: proteja el archivo

Restaurar (en el mismo servidor o en uno nuevo)

  1. En un servidor nuevo, instale primero OpenNCCM (secciones 3 a 5).
  2. Si la copia no incluye la clave, copie el secret.key original a /etc/opennccm/secret.key.
  3. Restaure:
$ sudo systemctl stop opennccm $ sudo opennccm-cli restore /ruta/opennccm-AAAAMMDD-HHMMSS.tar.gz $ sudo chown -R opennccm:opennccm /var/lib/opennccm /etc/opennccm $ sudo systemctl start opennccm
La clave es imprescindibleSin el secret.key correcto las configuraciones y contraseñas respaldadas no se pueden descifrar. Guárdela en un lugar seguro, separado de las copias (por ejemplo, en el gestor de contraseñas del equipo).

14. Actualizar a una versión nueva y volver atrás

Las actualizaciones usan el mismo instalador. Sus datos, la clave y la configuración se conservan.

Actualizar

$ cd ~ && rm -rf opennccm $ tar xzf opennccm-NUEVA.tar.gz && cd opennccm $ cat CHANGELOG.md # qué cambia en la versión $ sudo bash install.sh ==> Actualizando OpenNCCM 1.1.0 -> 1.2.0 en Ubuntu 24.04 LTS Copia previa en /var/lib/opennccm/pre-update/AAAAMMDD-HHMMSS_v1.1.0 (código + base de datos). Para volver atrás: sudo bash /home/USUARIO/opennccm/rollback-update.sh /var/lib/opennccm/pre-update/AAAAMMDD-HHMMSS_v1.1.0 $ sudo opennccm-cli version 1.2.0

La versión instalada también aparece al pie de todas las páginas. Los navegadores cargan automáticamente los estilos nuevos.

Volver a la versión anterior

$ sudo bash rollback-update.sh # lista las copias previas $ sudo bash rollback-update.sh /var/lib/opennccm/pre-update/AAAAMMDD-HHMMSS_v1.1.0
AtenciónVolver atrás restaura también la base de datos de ese momento: se pierden los respaldos y cambios registrados después de actualizar (la base descartada se conserva con el sufijo .descartada-…).

Buenas prácticas

  • Lea el CHANGELOG.md antes de actualizar.
  • Cree además una copia de recuperación con la clave y, si es una VM, una instantánea.
  • Actualice fuera del horario de respaldos programados.

15. PostgreSQL para instalaciones grandes

SQLite es suficiente para la mayoría de las redes. Para miles de equipos o varios administradores trabajando a la vez, use PostgreSQL. Hágalo antes de cargar datos (no hay migración automática de SQLite a PostgreSQL).

$ sudo apt install -y postgresql $ sudo -u postgres psql -c "CREATE USER ncm WITH PASSWORD 'CLAVE_SEGURA';" $ sudo -u postgres psql -c "CREATE DATABASE opennccm OWNER ncm;" $ sudo /opt/opennccm/.venv/bin/pip install psycopg2-binary $ sudo nano /etc/opennccm/opennccm.env # agregue la línea: NCM_DATABASE_URL=postgresql+psycopg2://ncm:CLAVE_SEGURA@localhost/opennccm $ sudo systemctl restart opennccm $ sudo opennccm-cli create-admin admin 'ClaveNueva123' $ sudo opennccm-cli seed

Con PostgreSQL las copias de recuperación usan pg_dump (instale postgresql-client) y se restauran con pg_restore.

Problemas frecuentes

SíntomaCausa probable y solución
La web no abreVer logs: journalctl -u opennccm -n 100 y sudo nginx -t. Revise el cortafuegos (puerto 443).
«No se pudo abrir syslog UDP/514» en el logOtro servicio usa el puerto (p. ej. rsyslog con recepción UDP activada). Desactive esa recepción o cambie NCM_SYSLOG_PORT en /etc/opennccm/opennccm.env.
Respaldo: «TCP connection to device failed» o timeoutSin conectividad o SSH cerrado. Pruebe ssh desde el servidor; revise ACL de VTY en el equipo.
Respaldo: «Authentication failed»Usuario/contraseña incorrectos en la credencial asignada.
Respaldo: «Pattern not detected»El prompt o el modo privilegiado no son los esperados: falta la contraseña de enable, o el device_type no corresponde al equipo.
Respaldo: «salida inválida»El comando de respaldo no existe en esa versión. Defina un comando de respaldo personalizado en el dispositivo.
Los cambios no se detectan en tiempo realEl equipo no envía syslog, lo envía desde otra IP, o un cortafuegos bloquea UDP 514. Verifique con sudo tcpdump -ni any udp port 514.
Telnet «no soportado»Esa plataforma no tiene variante Telnet en Netmiko: use SSH.
Olvidó la contraseña de adminsudo opennccm-cli reset-password admin 'NuevaClave123'
Firmware: «MD5 no verificado»Imagen dañada o espacio insuficiente; en Cisco habilite ip scp server enable.

17. Desinstalar

Antes de desinstalarCree y descargue una copia de recuperación con la clave si quiere conservar los datos.
$ sudo systemctl disable --now opennccm $ sudo rm -f /etc/systemd/system/opennccm.service /usr/local/bin/opennccm-cli $ sudo rm -f /etc/nginx/sites-enabled/opennccm /etc/nginx/sites-available/opennccm && sudo systemctl reload nginx $ sudo rm -rf /opt/opennccm # borra TODOS los datos y la clave: $ sudo rm -rf /var/lib/opennccm /etc/opennccm $ sudo userdel opennccm
